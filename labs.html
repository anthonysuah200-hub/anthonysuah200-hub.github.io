LAB 01 • BEGINNER

🔐 SecureBank Training Lab

A deliberately vulnerable fictional application created for learning about Broken Access Control.

01

The Scenario

SecureBank has two types of users:

  • Normal users
  • Administrators

The application correctly requires users to log in. However, the application contains an authorization mistake that allows a normal user to reach functionality intended for administrators.

🎯 Your Mission

Identify the difference between authentication and authorization and determine why the administrator area should be restricted.

Learning Objectives

🔑 Authentication

Understand how an application determines who a user is.

🛡️ Authorization

Understand how an application determines what an authenticated user is allowed to do.

🚧 Access Control

Learn how applications enforce boundaries between different user roles.

🔎 Security Analysis

Practice identifying security weaknesses in a controlled environment.

🐳 Run the Lab Locally

The laboratory runs inside Docker on your own computer. GitHub Pages only hosts the instructions; it does not execute Docker containers.

💻 Kali Linux Setup

Open your Kali Linux terminal and run: 

docker --version
docker compose version

Then navigate to the lab directory: 

cd ~/anthonysuah200-hub.github.io/labs/owasp-01-access-control

Start the training application: 

docker compose up --build

When the container starts, open this address in your browser: 

http://127.0.0.1:8080

🧠 Lab Questions

Question 1: What is the difference between authentication and authorization?

Question 2: What security weakness is represented by a normal user reaching administrator-only functionality?

🚨 Important

The SecureBank application is intentionally vulnerable and fictional. Use it only as a local training laboratory.

HOW THE LABS WORK

Learn → Analyze → Practice → Defend

1️⃣ Learn

Understand the security concept before touching the laboratory.

2️⃣ Analyze

Read the scenario and identify the security problem.

3️⃣ Practice

Use the isolated lab to investigate the concept safely.

4️⃣ Defend

Understand how developers and security professionals can prevent the weakness.
