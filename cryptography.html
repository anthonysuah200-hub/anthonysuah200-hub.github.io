Lesson 1 — What Is Cryptography?

Cryptography is the practice of protecting information by transforming it into a form that unauthorized people cannot easily understand or use.

Modern cybersecurity uses cryptography to protect passwords, financial transactions, messages, websites, files, databases and communication between devices.

Simple idea: Cryptography helps turn readable information into protected information and provides mechanisms for proving authenticity and integrity.

Cryptography is not the same thing as hiding information through secrecy alone. Good cryptographic systems are designed so that security depends on strong algorithms and properly protected keys.

Lesson 2 — Encryption and Decryption

Encryption transforms plaintext into ciphertext using an algorithm and a cryptographic key.

Decryption reverses that process and attempts to recover the original plaintext using the appropriate key.

Plaintext: Original readable information.

Ciphertext: Transformed protected information.

Encryption: Plaintext → Ciphertext.

Decryption: Ciphertext → Plaintext.

Symmetric Encryption

Symmetric encryption uses the same secret key for encryption and decryption. The communicating parties must therefore have a secure way to obtain and protect that key.

AES is a widely used symmetric encryption standard. It is used in many systems where efficient encryption of large amounts of data is required.

Asymmetric Encryption

Asymmetric cryptography uses a pair of mathematically related keys: a public key and a private key.

The public key can generally be shared, while the private key must be protected by its owner.

Lesson 3 — Hashing and Password Security

Hashing is a one-way transformation that produces a fixed-size output from input data. Cryptographic hash functions are designed to make it computationally difficult to recover the original input from the hash.

Hashing is commonly used for integrity checking and password storage. Password systems should use password-specific hashing algorithms designed to resist guessing attacks rather than simply storing passwords as plaintext.

Salt

A salt is additional unique data combined with a password before password hashing. A different salt should normally be used for each password record.

Salting helps prevent attackers from efficiently using precomputed tables of password hashes against many accounts.

Never treat Base64 encoding as password protection. Base64 is encoding, not encryption or cryptographic hashing.

Lesson 4 — Keys, Digital Signatures and Certificates

Cryptographic Keys

A cryptographic key is information used by a cryptographic algorithm to perform an operation such as encryption, decryption, signing or verification.

Protecting keys is extremely important. A strong algorithm cannot compensate for a private key that has been exposed.

Digital Signatures

Digital signatures can provide evidence that data was signed by the holder of a particular private key and can help detect changes to signed information.

Digital Certificates

Digital certificates bind information such as a public key to an identity or domain under a certificate authority's trust model.

Public Key Infrastructure

Public Key Infrastructure, commonly called PKI, is a collection of technologies, processes and trust relationships used to manage public-key certificates and related cryptographic identities.

Lesson 5 — TLS and HTTPS

TLS, or Transport Layer Security, is a cryptographic protocol used to protect network communication.

HTTPS uses HTTP over a TLS-protected connection. This helps protect data exchanged between a browser and a web server against unauthorized observation or modification during transmission.

Lesson 6 — Cryptography in Cybersecurity

Cryptography is used throughout cybersecurity. It can help protect information while stored, protect communication while it travels, verify integrity, authenticate systems and support secure identity management.

Security professionals must understand both the strengths and limitations of cryptography. Poor key management, weak passwords, outdated protocols and incorrect implementation can undermine an otherwise strong cryptographic design.

Common Applications

  • HTTPS websites
  • Secure messaging
  • VPN connections
  • Password protection
  • Digital signatures
  • Software integrity
  • Secure file storage
  • Authentication systems
  • Digital certificates
  • Cloud security
Security principle: Cryptography is a security tool, not a complete security strategy. It must be combined with authentication, authorization, secure configuration, monitoring and good key management.

📚 Cryptography Dictionary

Search the dictionary below to learn important cryptography and cybersecurity terms. Each definition contains a simple explanation and a practical example.

Cryptography Fundamentals

1. Cryptography

Cryptography is the science and practice of protecting information through mathematical techniques. It provides mechanisms for confidentiality, integrity, authentication and non-repudiation.

Modern cryptography is used in websites, applications, operating systems, databases and communication networks.

Example: HTTPS uses cryptographic techniques to protect web communication.

2. Plaintext

Plaintext is information in its original readable or usable form before encryption.

It can represent a message, document, password or other data that an application needs to process.

Example: "Hello World" can be plaintext before encryption.

3. Ciphertext

Ciphertext is the transformed output produced when plaintext is processed by an encryption algorithm.

Without the required cryptographic key and algorithm, the ciphertext should not reveal the protected information in a practical way.

Example: Encrypted banking traffic appears as protected ciphertext rather than readable text.

4. Encryption

Encryption transforms readable information into a protected form using an algorithm and a cryptographic key.

Its primary purpose is to help provide confidentiality so that unauthorized parties cannot easily read the protected data.

Example: A messaging application can encrypt messages before transmission.

5. Decryption

Decryption is the process of recovering usable plaintext from ciphertext using the appropriate cryptographic process.

The exact requirements depend on whether the system uses symmetric or asymmetric cryptography.

Example: A recipient's device decrypts an encrypted message for display.

6. Cipher

A cipher is an algorithm or method used to transform information according to defined cryptographic rules.

Modern cryptographic ciphers are designed using mathematical structures and are evaluated for resistance to known attacks.

Example: AES is a modern block cipher.

7. Cryptographic Key

A cryptographic key is data used by a cryptographic algorithm to perform operations such as encryption, decryption or signing.

Key security is critical because exposure of a secret key can compromise information protected with that key.

Example: An AES key can be used to encrypt data.

8. Symmetric Encryption

Symmetric encryption uses the same secret key, or related secret key material, for encryption and decryption.

It is generally efficient and is commonly used to protect large amounts of data.

Example: AES is commonly used for symmetric encryption.

9. Asymmetric Cryptography

Asymmetric cryptography uses mathematically related public and private keys.

Public keys can generally be shared while private keys must be protected. The system supports applications such as digital signatures and key establishment.

Example: Public-key cryptography is used in TLS and digital signatures.

10. Public Key

A public key is the shareable part of an asymmetric cryptographic key pair.

Depending on the cryptographic system, it can be used to verify signatures or participate in establishing protected communication.

Example: A website can provide a public key through its digital certificate.

11. Private Key

A private key is the secret part of an asymmetric cryptographic key pair.

It should be carefully protected because unauthorized access to a private key can allow impersonation or compromise cryptographic protections.

Example: A private key can be used to create a digital signature.

12. Key Pair

A key pair consists of a public key and a mathematically related private key.

Key pairs are fundamental to many public-key cryptographic systems.

Example: SSH authentication can use a public/private key pair.

Hashing and Password Security

13. Hash Function

A hash function takes input data and produces a fixed-size output called a hash or digest.

Cryptographic hash functions are designed to make certain forms of reversal and collision finding computationally difficult.

Example: SHA-256 produces a 256-bit digest.

14. Hash

A hash is the output produced by a hash function.

Hashes can be used to compare data, detect changes and support authentication systems.

Example: A downloaded file can be compared against a published hash.

15. SHA-256

SHA-256 is a member of the SHA-2 family of cryptographic hash functions and produces a 256-bit digest.

It is commonly used for integrity verification and many other security applications.

Example: Software publishers may publish SHA-256 hashes for downloaded files.

16. SHA-512

SHA-512 is another SHA-2 cryptographic hash function that produces a 512-bit digest.

Like other secure hash functions, it can help detect changes to data.

Example: An administrator can calculate a SHA-512 digest to verify a file.

17. Salt

A salt is unique additional data used with a password before password hashing.

Unique salts help ensure that identical passwords do not produce identical stored password hashes.

Example: Two users with the same password should still have different salted password hashes.

18. Password Hashing

Password hashing is the process of transforming passwords using a password-focused hashing scheme designed for secure storage.

Modern password storage should use suitable password hashing algorithms and unique salts rather than storing plaintext passwords.

Example: Argon2id, scrypt and bcrypt are designed for password hashing.

19. Brute-Force Attack

A brute-force attack systematically tries many possible passwords, keys or other values until one succeeds.

Strong passwords, rate limiting, multifactor authentication and appropriate password hashing can reduce the effectiveness of password guessing.

Example: Repeatedly testing password guesses against an account is password brute forcing.

20. Dictionary Attack

A dictionary attack uses a list of likely passwords or words instead of trying every possible combination.

Passwords based on common words or predictable patterns are more vulnerable to this type of guessing.

Example: Testing a password list containing common passwords is a dictionary attack.

Algorithms and Cryptographic Techniques

21. AES

AES, or Advanced Encryption Standard, is a symmetric block cipher widely used to protect digital information.

AES supports key sizes of 128, 192 and 256 bits.

Example: AES can be used to encrypt stored files or application data.

22. RSA

RSA is a public-key cryptographic algorithm historically used for applications including encryption and digital signatures.

Modern systems often use other mechanisms for efficient key establishment, but RSA remains important for understanding public-key cryptography.

Example: RSA can be used for digital signatures.

23. ECC

Elliptic Curve Cryptography is a family of public-key cryptographic techniques based on mathematical properties of elliptic curves.

ECC can provide strong security with comparatively small key sizes for suitable cryptographic operations.

Example: Elliptic-curve algorithms are widely used in modern TLS and secure communications.

24. HMAC

HMAC stands for Hash-based Message Authentication Code. It combines a cryptographic hash function with a secret key.

HMAC can provide integrity and authentication of messages when the communicating parties share the secret key.

Example: HMAC-SHA256 uses SHA-256 together with a secret key.

25. Nonce

A nonce is a value intended to be used once within a particular cryptographic context.

Correct nonce usage can help prevent replay or other cryptographic weaknesses in protocols and encryption schemes.

Example: A protocol may generate a unique nonce for each protected message.

26. Initialization Vector

An initialization vector, commonly called an IV, is an input used by certain encryption modes to provide variation between encryption operations.

IV requirements depend on the specific algorithm and mode, and incorrect reuse can create serious security problems.

Example: Some block cipher modes require a unique IV for each encryption operation.

27. Encryption Mode

An encryption mode defines how a block cipher is applied to data larger than one block.

Different modes provide different security properties and have different requirements for IVs, nonces and authentication.

Example: GCM is an authenticated encryption mode commonly used with AES.

28. Authenticated Encryption

Authenticated encryption provides confidentiality together with integrity and authenticity protection for encrypted data.

This helps detect unauthorized modification of protected messages.

Example: AES-GCM is a commonly used authenticated encryption construction.

Digital Signatures and Identity

29. Digital Signature

A digital signature is a cryptographic value generated using private-key material and verified using corresponding public-key information.

It can help demonstrate who signed data and whether the signed data was modified after signing.

Example: Software can be digitally signed so users can verify its publisher.

30. Digital Certificate

A digital certificate contains information such as a public key and identity information and is digitally signed by a certificate authority or another trusted issuer.

Certificates help systems establish trust relationships for public-key cryptography.

Example: Websites use TLS certificates to establish their cryptographic identity.

31. Certificate Authority

A Certificate Authority, or CA, is an organization or system that issues and signs digital certificates according to defined certificate policies.

Operating systems and browsers maintain trusted CA information used when validating certificates.

Example: A browser checks whether a website certificate chains to a trusted CA.

32. PKI

PKI stands for Public Key Infrastructure. It includes technologies, processes and policies used to manage public-key certificates and trust relationships.

PKI supports applications such as TLS, digital signatures and certificate-based authentication.

Example: HTTPS relies on certificate and trust infrastructure.

33. Certificate Chain

A certificate chain is a sequence of certificates connecting an end-entity certificate to a trusted root certificate.

Each certificate in the chain can help establish trust in the certificate below it.

Example: A browser may validate a website certificate through an intermediate CA to a trusted root.

34. Root Certificate

A root certificate belongs to a trusted root certificate authority and forms the top of a certificate trust hierarchy.

Root certificates are normally distributed through operating systems, browsers or organizational trust stores.

Example: A browser may trust a website because its certificate chains to a trusted root.

Secure Communication

35. TLS

TLS stands for Transport Layer Security. It is a protocol designed to protect communication between networked applications.

TLS can provide confidentiality, integrity and authentication depending on how it is configured and used.

Example: HTTPS uses TLS to protect browser-to-server communication.

36. HTTPS

HTTPS is HTTP transported through a TLS-protected connection.

It helps protect web traffic from unauthorized observation and modification while the connection is properly secured.

Example: https://example.com indicates HTTP over a TLS connection.

37. End-to-End Encryption

End-to-end encryption is a communication design in which message content is encrypted so that the intended endpoints are able to decrypt it.

The exact security properties depend on the application's architecture, key management and implementation.

Example: Some secure messaging systems use end-to-end encryption for message content.

38. VPN

A Virtual Private Network creates a protected communication channel across an underlying network.

VPNs can use cryptographic protocols to protect traffic between endpoints or networks.

Example: An employee may use a VPN to securely connect to an organization's network.

39. SSH

Secure Shell, or SSH, is a protocol used for secure remote access and other protected network operations.

SSH can use public-key cryptography for authentication and encryption to protect the session.

Example: Administrators commonly use SSH to securely manage Linux servers.

40. Perfect Forward Secrecy

Perfect Forward Secrecy, or PFS, is a property where compromise of a long-term private key does not automatically allow an attacker to decrypt previously recorded sessions.

Modern secure protocols can use ephemeral key exchange mechanisms to provide this property.

Example: Ephemeral Diffie-Hellman key exchange can support forward secrecy.

Cryptographic Attacks and Weaknesses

41. Cryptanalysis

Cryptanalysis is the study of methods for analyzing cryptographic systems and finding weaknesses in their algorithms or implementations.

Security researchers use cryptanalysis to evaluate whether cryptographic designs resist practical attacks.

Example: Researchers may analyze an algorithm for weaknesses that reveal information about protected data.

42. Collision

A hash collision occurs when two different inputs produce the same hash output.

Cryptographic hash functions are designed to make useful collision attacks computationally impractical.

Example: A collision in a weak hash algorithm can undermine applications that depend on unique digests.

43. Rainbow Table

A rainbow table is a precomputed data structure designed to speed up recovery of plaintext values from certain unsalted password hashes.

Unique salts significantly reduce the usefulness of precomputed tables against password databases.

Example: A unique salt for every password makes a single precomputed table much less useful.

44. Key Management

Key management covers the generation, storage, distribution, rotation, backup, revocation and destruction of cryptographic keys.

Poor key management can weaken otherwise strong cryptographic algorithms.

Example: An organization may rotate encryption keys according to a defined security policy.

45. Key Rotation

Key rotation is the process of replacing a cryptographic key with a new key according to a defined policy.

Rotation can limit the amount of information protected by one key and reduce the impact of certain key compromises.

Example: A service may periodically replace an API encryption key.

46. Key Revocation

Key revocation is the process of declaring a key or certificate invalid before its normal expiration.

Revocation may be necessary when credentials are compromised, misissued or no longer trusted.

Example: A compromised certificate can be revoked so clients stop trusting it.

Encoding and Related Concepts

47. Encoding

Encoding converts data into another representation so that it can be stored, transmitted or processed in a particular format.

Encoding does not inherently provide confidentiality.

Example: UTF-8 encodes characters into bytes.

48. Base64

Base64 is an encoding scheme that represents binary data using a set of printable characters.

Base64 is not encryption because anyone can decode it without a secret cryptographic key.

Example: Base64 is often used to represent binary data in text-based formats.

49. Steganography

Steganography is the practice of hiding information inside another medium, such as an image, audio file or document.

Unlike encryption, its main purpose is often to conceal the existence of the message rather than simply protect its contents.

Example: Data can be hidden inside an image while the image still appears normal.

50. Non-Repudiation

Non-repudiation refers to mechanisms intended to provide evidence about the origin or approval of an action or message.

Digital signatures can contribute to non-repudiation, although the exact legal and technical meaning depends on the surrounding system and policies.

Example: A digitally signed document can provide evidence that a particular private key signed it.

51. Integrity

Integrity means protecting information against unauthorized or undetected modification.

Hashes, MACs and digital signatures can provide different forms of integrity protection.

Example: A file hash can help detect whether a downloaded file changed.

52. Confidentiality

Confidentiality means preventing unauthorized parties from accessing protected information.

Encryption is one of the primary technical mechanisms used to support confidentiality.

Example: Encrypting a private document can help prevent unauthorized reading.

53. Authentication

Authentication is the process of establishing or verifying the identity of a user, device or system.

Cryptographic credentials such as certificates, security keys and signed challenges can support authentication.

Example: SSH can authenticate a user using a public/private key pair.

54. Authorization

Authorization determines what an authenticated user, application or system is allowed to access or perform.

Cryptography can support authorization systems, but authorization itself is a separate security function.

Example: An authenticated administrator may be authorized to access server settings.

55. Defense in Depth

Defense in depth means using multiple complementary security controls instead of depending on one protection mechanism.

Cryptography should therefore be combined with strong authentication, secure configuration, monitoring, access control and other controls.

Example: A system may use encryption, MFA, access control and monitoring together.
